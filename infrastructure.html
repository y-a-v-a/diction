Diction — Infrastructure Reference

Overview of the deployment pipeline and AWS setup for diction.vincentbruijn.nl.

1. Pipeline Overview

GitHub (manual trigger) → Docker build → ECR push → ECS Express Mode → ALB → diction.vincentbruijn.nl

2. GitHub Actions Workflow

File: .github/workflows/docker-build.yml

  • Trigger: manual via workflow_dispatch (Actions tab → Run workflow)
  • Authenticates to AWS via OIDC (no long-lived credentials)
  • Builds the Docker image and pushes to ECR with :latest and :<sha> tags

GitHub repo settings (Settings → Secrets and variables → Actions)

3. AWS Components

ECR (Elastic Container Registry)

Repository: diction in eu-west-1. Stores the Docker images.

ECS Express Mode

Runs the container on Fargate. Automatically provisions ALB, target groups, and auto-scaling.

  • Container port: 3000
  • Health check path: /

IAM — OIDC Trust (GitHub → AWS)

  • Identity provider: token.actions.githubusercontent.com
  • IAM role trust policy scoped to repo:y-a-v-a/diction:*
  • Role permissions: ecr:GetAuthorizationToken, ECR push actions on the diction repository

IAM — ECS Task Execution Role

Must have secretsmanager:GetSecretValue permission on the diction secret.

6. Deploying a New Version

  1. Push code to main
  2. Go to GitHub Actions → Build and Push to ECR → Run workflow
  3. After the image is pushed, update the ECS service: 
    aws ecs update-service --cluster <cluster> --service <service> --force-new-deployment
    Or use the ECS console: select service → Update → Force new deployment

7. Dockerfile

File: Dockerfile in the project root.

  • Base image: node:20-alpine
  • Installs production dependencies only (npm ci --omit=dev)
  • Runs as non-root node user
  • Exposes port 3000
  • Includes a health check on /
Note: The .env file is excluded from the Docker image via .dockerignore. All secrets are injected at runtime via ECS + Secrets Manager.
